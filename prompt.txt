# Project: Next-Generation Bible & Church Presentation Software

You are a senior desktop application architect, UI/UX engineer, multimedia systems engineer, and product reverse-engineering specialist.

I have the following applications installed locally:

- PewBeam
- FreeShow
- OBS Studio

I am building my own open-source church presentation and live-production application.

The goal is NOT to copy proprietary source code, assets, branding, or implementation details from PewBeam or OBS.

Instead, study how these applications behave from a user's perspective, identify their strongest concepts and workflows, and use those ideas to design a substantially better, original application.

FreeShow is open source and should be studied deeply at the architectural/product level where its source is available.

PewBeam should be treated as a black-box product. Analyze its visible UI, workflows, presentation behavior, configuration, shortcuts, outputs, and user experience without attempting to extract proprietary source code.

OBS should be studied as the reference for professional live-production concepts such as scenes, sources, preview/program workflows, transitions, audio/video routing, multiview, hotkeys, recording, streaming, and extensibility.

# 16. PERFORMANCE

This application may run for several hours during a live church service.

Therefore:

- avoid UI freezes
- avoid memory leaks
- preload media
- cache thumbnails
- cache Bible data
- handle large media libraries
- recover from media errors
- avoid blocking the UI thread
- use background workers where appropriate

A presentation operator must never experience:

"Application Not Responding"

during a live service.
